# Connecting the real systems

This repository is a working design and interaction concept. It is not an official Eshet Tours website, a live booking engine or a merchant checkout. No inventory, quote, visa decision or cancellation entitlement is confirmed by the demonstration. The footer disclosure and `noindex` must remain until an authorised official launch.

## What is working in demonstration mode

- Localised interfaces and structured planner options, including scripted requests without an API key.
- Package arithmetic, comparison tools, editable ribbon, local preferences and clearly marked example data.
- An explicit preview and consent step before submitting a brief.
- Server routes for `/api/planner`, `/api/visa`, `/api/tours` and `/api/brief`.
- A password-protected demonstration inbox when `ADMIN_PASSWORD` is configured.
- A real webhook request only when a webhook URL is configured and the user explicitly submits a consented lead. Without that connection, the interface reports demo handling rather than pretending an agent received it.
- A WhatsApp link only when a verified destination number is configured. Opening WhatsApp does not silently send a message; the traveller controls sending there.

AI credentials enable the provider integration; they do not connect inventory or turn generated examples into verified prices. Live answers must retain the same source limits and example labels.

## Server environment

Use `.env.example` as the current variable contract and copy it to a private `.env.local` for local work. Never commit values. For a hosted deployment, enter the same variables through the host's environment settings, then redeploy. A provider key, webhook URL, WhatsApp number and admin password are separate capabilities; setting one does not enable the others.

The application must remain fully usable in demo mode without any AI key. Missing integration settings should produce a clear demonstration state rather than an apparent completed booking, enrolment or message delivery. Never include secret values in client bundles, screenshots, analytics, documentation or logs.

## Persistence, admin and security boundaries

The inbox storage is a development demonstration. A local filesystem may survive a local restart; a serverless temporary filesystem does not provide durable, shared records. Before using real traveller data, replace it with an encrypted database, authenticate individual staff through SSO, enforce roles and sessions, log access, establish deletion/retention and test backup recovery. A shared `.env` password is adequate for showing the concept privately, not for operating a production travel desk.

Add durable outbox delivery and idempotency before relying on webhook delivery for business operations. Validate signatures on callbacks. Keep network destinations and credentials in server configuration. Use HTTPS and never place traveller details in public cache keys or analytics events. Protect against automated abuse with distributed limits; process-local demonstration limits do not cover a scaled deployment.

## Currency and price contract

Use ILS as the display default. Every price must include its unit: per traveller, per person in a double room, per room, or per couple per night; show the board basis where applicable. Foreign-currency fees stay explicitly labelled in their original currency. Converting or combining them requires a stated, sourced exchange rate and timestamp. The concept does not invent those rates.

Never remove example labels until the displayed value comes from a verified quote with provenance and expiry. A successful AI response does not constitute that verification.

## Go-live sequence

1. Approve the factual, legal, pricing and contact items in `CONFIRM_WITH_CLIENT.md`.
2. Connect inventory and repricing in a provider sandbox. Exercise sold-out, price-change, cancellation, payment-failure and provider-timeout paths.
3. Connect CRM, club and messaging to test recipients. Verify the exact preview/payload match, consent record, deduplication and delivery reporting.
4. Replace demonstration storage/authentication; complete privacy, security and independent accessibility reviews, including IS 5568 applicability.
5. Validate all three languages with Eshet teams, real devices, assistive technology and real content. Repeat build, lint, type checks, tests, Lighthouse and axe after integrations.
6. Obtain explicit authorisation for production deployment, real recipients, brand use and search indexing. Configure the official domain and final production privacy/legal copy; remove `noindex` only as part of that authorised launch.

## Outbound access

The key-free demo requires no travel or AI API access. When enabling a provider in a restricted cloud environment, permit `api.openai.com` or `api.anthropic.com` for the selected provider and the exact approved HTTPS host of `LEAD_WEBHOOK_URL`. Keep credentials server-side and use normal TLS verification. Official visa sources and WhatsApp are visitor-opened links, not background API integrations.

## Cloudflare runtime

Cloudflare deployments use the configured `LEADS_DB` D1 binding for durable enquiry records. The Node development fallback still uses `.data`; Vercel still needs an external durable store. See [docs/CLOUDFLARE.md](docs/CLOUDFLARE.md) for migrations, account access and deployment commands.
